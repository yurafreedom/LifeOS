## Part 2 — update history

**Version policy.** Build version = `apps/web/package.json` `version` (0.1.0).
Release = entry `released` + semver + real date. Unreleased = at most one entry,
first, no version, no date. No formal release exists (the only tag,
`adaptive-analytics-design-accepted`, is a design milestone), so the page shows
one honest "Unreleased · development build" entry.

**Canonical source.** `apps/web/src/data/releaseNotes.json` (schema v1),
validated by `apps/web/src/domain/releaseNotes.js` (pure, used by the app, the
generator and tests). Root `CHANGELOG.md` is generated by
`npm run release-notes` (`apps/web/scripts/release-notes.mjs` +
`src/domain/releaseNotesChangelog.js`, labels from the `upd_*` locale keys);
`--check` and a test fail on drift. Content describes only what this build
contains: branding, interface font, Tasks/Waiting/dates, Calendar, account
security, encrypted documents (as server-configured), sounds; L2 only under
technical details; limitations state server-side (not E2E) encryption, the
unencrypted snapshot/analytics/browser data, no extraction/loan/charts/reminders,
mail dependency, no passkeys/Diia/BankID/banks, missing create paths. Commit refs
are verified ancestors of HEAD by a test.

**UI.**
- Route `#/updates` (lazy chunk `UpdatesPage`, 3.4 kB JS + 3.3 kB CSS); Settings
  gains **о JENKIN / про JENKIN** (`#/settings/about`, build version, release
  line, link). The sidebar keeps Settings highlighted on `#/updates`; the page
  links back to `#/settings/about`. Existing navigation unchanged.
- `PageHeader` (paradise hero in paradise), compact intro, `<ol>` of `.panel`
  cards with a satin sheen; each header is an `h3 > button` with
  `aria-expanded`/`aria-controls` showing version, status pill and date (or
  "release date not assigned") before expansion; body is a labelled region;
  groups `h4` + lists; technical details in native `<details>`; refs as `<code>`.
- Newest entry open initially, others collapsed; toggles are independent.
- Focus: 2 px `--jenkin-focus` outline on headers, summary and back link.
  Reduced motion: no chevron transition. Long text: `overflow-wrap: anywhere`.
  Paradise: the intro/back link/state text gets a card-surface plate.
- Empty and error states exist only because the component accepts data that
  could be empty/invalid (both tested).
- RU/UK +26 keys each (pins 2089/2088). Route registry 22 → 23.
