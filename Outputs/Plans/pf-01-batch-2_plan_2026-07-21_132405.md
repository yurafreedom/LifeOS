## 1. Outcome

Create a Python 3.11 FastAPI service that:

1. bootstraps exactly one initial account using a server secret;
2. authenticates accounts using Argon2id passwords and opaque database sessions;
3. stores only hashed session tokens and sends the raw token only in an HttpOnly cookie;
4. stores one user-owned JSONB Life OS snapshot per account;
5. prevents cross-account access by deriving `user_id` only from the authenticated session;
6. prevents stale overwrites with an atomic expected-revision predicate;
7. exposes a same-origin `/api/v1` contract for Batch 3 without changing the frontend now.

**VERIFIED current boundary:** Vite already proxies `/api` to the local backend (`apps/web/vite.config.js:3-13`). Current state is a single `version: 2` JSON object (`apps/web/src/context/LifeDataContext.jsx:88-115`) persisted as `lifeOsState` (`apps/web/src/lib/storage.js:19-20`).

## 2. Approved architecture refinements

These refinements close the Discovery gaps and become binding only if this Plan is approved.

### 2.1 State initialization

- Bootstrap creates `users` and `sessions` rows, but no `user_snapshots` row.
- `GET /api/v1/state` returns typed `404 state_not_initialized` when the authenticated user has no row.
- First `PUT` must send `expected_revision: 0`; an atomic PostgreSQL insert creates revision 1.
- Later PUTs must send the last acknowledged positive revision; one guarded update increments it by exactly one.
- `{}` remains a valid initialized payload and is never used as an empty-state sentinel.

### 2.2 Email identity

- Validate input with Pydantic `EmailStr`/`email-validator` without DNS deliverability checks.
- Canonicalize by trimming and applying Unicode `casefold()` to the full normalized address.
- Persist only the canonical address.
- Enforce a unique PostgreSQL expression index on `lower(email)` as DB-level defense.
- Do not add the `citext` extension. PostgreSQL confirms an ordinary `UNIQUE` text index is case-sensitive and a unique `lower(...)` index enforces case-insensitive uniqueness. [PostgreSQL expression indexes](https://www.postgresql.org/docs/current/indexes-expressional.html)

### 2.3 Database access

- Use synchronous SQLAlchemy 2 sessions with psycopg 3.
- FastAPI route handlers that touch the DB are ordinary `def` functions, so FastAPI runs them outside the event loop.
- Engine creation is lazy; importing `create_app` does not connect to PostgreSQL.
- Service functions own transaction boundaries; route modules do not issue `commit()` directly.

### 2.4 Sessions and cookies

- Generate 32 random bytes with `secrets.token_urlsafe(32)`; store `sha256(raw_token)` only.
- Absolute TTL: 30 days (`2_592_000` seconds), configurable.
- Multiple sessions per user are allowed.
- Touch `last_seen_at` at most once per 15 minutes; expired sessions are invalid and opportunistically removed.
- Production cookie: `__Host-lifeos_session`, `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`, no `Domain`.
- Development/test cookie: `lifeos_session`, non-Secure only when `LIFEOS_ENVIRONMENT != production`.
- Configuration validation rejects production with `LIFEOS_COOKIE_SECURE=false`.
- OWASP recommends CSPRNG-generated opaque IDs, HttpOnly/Secure/SameSite and `__Host-` for host-bound session cookies. [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

### 2.5 CSRF and request origin

- No CORS middleware; frontend uses the Vite proxy locally and same-origin hosting later.
- Every unsafe endpoint (`bootstrap`, `login`, `logout`, state PUT) rejects `Sec-Fetch-Site: cross-site`.
- Then require exact match against configured allowed origins using `Origin`; use exact-origin `Referer` only as fallback.
- Reject unsafe requests when both source headers are absent.
- Require `application/json` for bootstrap/login/state PUT; logout has no body.
- OWASP treats SameSite as defense-in-depth and recommends Origin/Referer validation for unsafe requests. [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)

### 2.6 Snapshot size/schema

- Maximum request body for state PUT: 5 MiB (`5_242_880` bytes), enforced before full body parsing by ASGI middleware.
- `payload` must be a JSON object, not any JSON value.
- Batch 2 supports exactly `schema_version: 2`.
- `payload.version` is required and must equal `schema_version`.
- Pydantic request models use `extra="forbid"`; `user_id` and unknown ownership fields are rejected.
- Snapshot bodies, passwords, bootstrap tokens and raw session tokens are never logged.

### 2.7 Login throttling boundary

- Batch 2 implements generic 401 responses and dummy-hash verification for unknown email addresses, following current FastAPI guidance. [FastAPI password hashing](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)
- It does **not** add a process-local limiter or a fourth database table: either would create misleading multi-worker semantics or expand the approved schema.
- **Production gate:** Batch 4/VPS reverse proxy must rate-limit `/api/v1/auth/login` and `/bootstrap` before public exposure. Until then, the API is local/test-only.
- Password recovery remains excluded. Losing the only password requires an explicit future admin recovery task; this risk is documented, not hidden.

### 2.8 Static frontend serving

- Batch 2 is API-only and does not use `StaticFiles` or mount a SPA.
- **Reason:** `apps/web/dist` is ignored (`apps/web/.gitignore:1-2`), and repository rules require Dockerfile directory provisioning in the same commit as any StaticFiles runtime path. Docker/combined serving belongs to Batch 4.
- `create_app()` therefore imports and runs without frontend build artifacts. Batch 4 adds the combined same-origin artifact.

| Caller/endpoint | Preconditions | Success | Failure behavior | DB/write delta |
|---|---|---|---|---|
| Render/VPS health probe → `GET /api/healthz` | none | `200 {"status":"ok"}` after `SELECT 1` | `503 {"code":"database_unavailable"}`; no internal detail | read-only |

| Batch 3 client → first `PUT /api/v1/state` | valid cookie, origin, JSON, ≤5 MiB, expected 0 | `201 StateEnvelope(revision=1)` | 409 if row appeared; 413/415/422 validation failures | `INSERT ... ON CONFLICT DO NOTHING RETURNING` for authenticated `user_id` |

## 7. Database migration

### `users`

- `id UUID PRIMARY KEY`
- `email VARCHAR(320) NOT NULL`
- `password_hash TEXT NOT NULL`
- `is_active BOOLEAN NOT NULL DEFAULT true`
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- unique expression index `uq_users_email_lower ON users (lower(email))`

### `sessions`

- `id UUID PRIMARY KEY`
- `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`
- `token_hash CHAR(64) NOT NULL UNIQUE`
- `expires_at`, `created_at`, `last_seen_at TIMESTAMPTZ NOT NULL`
- indexes `ix_sessions_user_id`, `ix_sessions_expires_at`

### `user_snapshots`

- `user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE`
- `schema_version INTEGER NOT NULL`
- `revision BIGINT NOT NULL DEFAULT 1`
- `payload JSONB NOT NULL`
- `created_at`, `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- checks: `schema_version > 0`, `revision > 0`, `jsonb_typeof(payload) = 'object'`

`upgrade()` creates tables in dependency order `users → sessions → user_snapshots`; `downgrade()` drops in reverse. No extension, trigger or seed data.

## 8. State/session lifecycle and race handling

| State | Writer | Reader | Clearer/expiry | Restart/corrupt/double-tap/deploy race |
|---|---|---|---|---|
| User | bootstrap only | login/session/me | no deletion in PF-01 | DB-persistent; duplicate bootstrap serialized by advisory lock; unique lower-email is final defense. |
| Session | bootstrap/login | cookie dependency via token hash | logout, absolute expiry, opportunistic cleanup | DB-persistent across app restart; random/unknown token → generic 401; repeated login creates separate allowed sessions; raw token never stored. |
| Snapshot | authenticated PUT | authenticated GET | no clear/reset in Batch 2 | DB-persistent; invalid shape/version rejected before write; double PUT with same N produces one winner + one 409; old/new web deploy race fails closed on schema version. |
| Bootstrap capability | environment secret | bootstrap service only | effectively disabled once any user exists | process restart does not reopen bootstrap; advisory lock serializes competing processes. |
| localStorage snapshot | no Batch 2 change | existing frontend only | existing hard reset | remains local source until explicit Batch 3 import; API never reads browser storage automatically. |

The state service uses authenticated `user_id` only. API request schemas contain no tenant/user owner field. Session resolution is the sole exception to “queries receive user_id”: it starts from `token_hash`, then derives the trusted user ID for every later operation.
